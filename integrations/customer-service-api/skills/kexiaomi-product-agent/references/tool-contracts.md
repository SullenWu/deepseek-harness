# 只读工具契约

SKILL描述调查方法，不授予数据权限。仅在运行环境真实提供工具时调用。

## API-MCP 使用条件

产品介绍、导航入口、操作步骤、使用前提和通用规则由产品 Skill 索引与文档提供，不调用 API-MCP。只有结论必须依赖当前门店、当前账号或具体业务对象的实时私有事实时，才使用 `mcp__lingke_api__search_capabilities` 和 `mcp__lingke_api__invoke_capability`。

混合问题先用产品资料处理通用部分，再仅为尚未解决的当前事实检索并调用能力。客户提到会员、会员卡、课程、预约等业务实体，或者运行时提供了 MCP 工具，都不单独构成调用理由。该规则按证据需求判断，不按固定问法或关键词路由。

每个 HTTP 请求都会产生新的工具世代。`invoke_capability` 只在当前请求成功执行 `search_capabilities` 并返回候选项后才存在；历史轮次出现过的工具名、候选项、引用和授权不能在本轮复用。调用失败时不得原样重复同一参数；应根据错误改变取证步骤、使用产品知识、提出一个必要问题，或明确说明当前证据不足。

## search_product_logic

按产品、业务域、实体、操作和用户问题检索结构化产品索引。结果必须包含证据等级、源码快照和标题路径。

## 当前已接入工具

- `query_business_data`：依据本轮下发的运行查询目录生成结构化查询计划，由 DuckAI 进程内的产品 Skill 数据库工具转换为参数化 `SELECT` 并直接执行。允许计划引用目录授权的逻辑数据源、表、字段、别名和关联；不得提交原始 SQL、物理数据库名、StoreId、TenantId、UID、手机号或内部业务主键。

`query_business_data` 使用的原始手机号只在当前请求内进入 DuckAI 本地参数绑定。模型只能看到 `[已提供会员手机号]`，Redis 历史、普通日志和工具结果都不能包含原始号码。

## 上游引用补齐

下游查询要求 `CardId`、`UserId`、`ChildCardId` 等内部引用时，引用本身属于工具侧缺口，不能要求客户提供。Agent 应使用当前开放的上游定位能力生成引用；如果该定位能力还缺少客户能够提供的信息，则只询问其参数契约明确支持的一项最小定位信息。客户提供后由服务端完成敏感值注入和短期引用保存，模型不能把敏感值或内部 ID 写入 `arguments`。

API-MCP 搜索服务会按引用字段类型反向匹配本次已启用能力中的 `reference-only` 输出，并把生产者加入同一份短期能力授权。搜索结果中的 `ReferenceResolutions` 给出下游字段与生产者候选，生产者自身的 `MissingCustomerInputs` 给出当前尚缺的客户输入、接口字段说明和 JSON Schema。Agent 必须消费这两组结构化元数据，不维护“目标接口 → 定位接口”问题路由，也不能只凭接口名称猜测客户输入。

该发现规则覆盖整份运行时 MCP 清单：新增接口只要正确声明请求字段来源和响应字段暴露策略即可参与匹配。Profile 中的主体定位器属于经过安全审核的优先生产者；没有该类优先项时，服务端从无需其他上游引用、必填公开参数更少的兼容生产者中选择。引用令牌在执行阶段仍会按同一规范化字段类型、产品、Profile、门店、会话和有效期复核。

不得把姓名、昵称、卡名等客户信息提交给不支持这些字段的定位接口，也不得因为上游引用暂缺就把原查询改成后台操作指导或直接转人工。若没有可调用的定位能力，应如实保留能力缺口；不能伪造引用或假装查询已经完成。

## query_business_data

依据运行查询目录生成结构化查询计划，由 DuckAI 本地通用编译器生成参数化 `SELECT` 并直接查询课小秘数据库。目录中的授权表、字段和关联可以作为计划标识符；模型不得提交原始 SQL、物理数据库名、StoreId、TenantId、UID、手机号或内部业务主键。

- 语义字段、可用关联和状态枚举必须来自本轮下发的运行白名单子集；完整物理目录和自动生成目录本身不等于授权。
- 商家可使用的软件订购、餐饮、商城、分销、短信和企微等模块可以进入运行目录，但各分组仍按 `fieldPolicy` 只开放完成调查所需的业务状态、金额、数量和时间等字段；订单定位号、收件信息、消息正文、开放平台标识、凭据和内部人员标识不得返回。
- 只能提交结构观察中已经列出的表、字段和关系；字段用法必须匹配 `usages`，字段聚合必须匹配 `aggregates`。统计表行数使用 `column="*"`、`aggregate="count"`，不能聚合仅供身份或关系过滤的 UID/ID 字段。
- 会员手机号只能绑定到 `users.user_mobile` 或 `user_card.card_tag` 的 `member-mobile`；未领卡会员的 `user_card.uid=0` 只能使用服务端固定的 `unclaimed-member`。订单收件手机号、员工手机号等其他字段不得复用该值源。三种值来源都不得携带模型提供的实际值。会员身份与具体持卡的关联规则见 [会员身份与持卡链路](member-card-identity-chain.md)。
- 当前操作人 UID 只允许绑定到已审核的创建人、修改人字段；业务实体的 `uid`、`user_id`、`staff_id` 不能仅凭同名字段自动当作当前操作人。
- StoreId 和 OperatorUid 来自已验证会话；DuckAI 再以 unionid、员工关系和门店状态实时复核并取得 TenantId，不能接受模型或客户正文提供的隔离范围。
- 主表和每个关联表别名都由 DuckAI 本地编译器分别注入 `store_id`、`tenant_id` 隔离条件，不能只限制主表。
- 只能使用只读账号，在显式只读事务中执行单条语句，超时 5 秒、最多 20 行；禁止 `SELECT *`、子查询逃逸、UNION、注释、函数延时和任何写操作。
- 返回业务事实及证据边界，不向模型暴露 SQL、内部主键、手机号、开放平台标识、备注正文或未审核字段。
- 财务分库由 DuckAI 读取当前产品 Skill 私有 `runtime/data-access.local.json`，按精确租户、区间、模数回退的既有顺序选择目标数据库。该私有文件不会作为知识下发给模型。`TenantData0`～`TenantData9` 可以共用已确认的同构字段白名单，但只复用结构，不复用连接或数据；目标分片未覆盖或连接失败时必须拒绝执行，不能改查其他分片猜测。

该工具只在服务端已经确认当前产品为课小秘、当前操作人和门店关系有效时下发。模型仍须以运行时实际收到的工具定义为准。

## 数据不可用后的知识兜底

业务数据查询失败或返回空结果时，Agent 在输出最终答复前必须调用产品知识工具。检索继续携带服务端保存的原始客户目标，模型根据当前证据缺口自主选择检索词、文档和答复，不在 DI 层固化问题、页面或答案。知识兜底应优先寻找能直接展示、汇总或验证原目标的产品能力，不能因为问题包含某个实体名称就自动退化为普通列表页。

## 后续扩展契约

以下名称描述未来可扩展的能力类型，不代表当前运行环境已经提供对应工具。模型只能调用运行时实际下发的工具定义。

## read_business_facts

读取已授权对象的状态、有效期、数量、余额、配置和资格等事实。ProductCode、StoreId 和 OperatorUid 必须由服务端注入。

## read_business_relations

读取会员—课卡—课程、账号—员工—门店、课次—预约—消费等关系。结果只返回完成当前调查所需的最小字段。

## read_operation_trace

按服务端提供的 requestId、错误码或安全操作引用读取接口阶段和业务结果，不返回请求正文、完整响应、密钥或无关客户数据。

## read_temporary_state

读取经过授权的二维码、绑定、登录或幂等临时状态。不能允许模型提交任意 Redis 键。

所有工具必须只读、限制轮次、限制返回量并记录不含敏感值的审计事件。工具失败时说明缺少证据，不得推断查询成功。
