# 证据规则

## 优先级

1. 当前运行环境的只读业务数据、请求结果和操作追踪。
2. 当前服务端 Controller、Provider、DAO、任务及明确校验。
3. 当前客户端真实调用顺序和前端预判。
4. 已有产品文档、规划和历史行为。
5. 字段名、页面文案、代码注释和模型常识。

## 索引证据等级

- `服务端强制`：可用于解释业务规则，但不能自动证明生产部署版本和当前对象状态。
- `前端预判`：只能说明页面如何提示或阻断，不能代替服务端权限和事务结论。
- `配置驱动`：必须读取当前门店配置后才能确定。
- `平台差异`：必须先确认微信、支付宝、H5、App 或 PC。
- `源码推断`：只能形成待验证假设。
- `冲突`：保留多个解释，继续查接口、数据或运行证据。
- `历史兼容`：不能自动当作当前主入口或对外销售能力。
- `接口缺口`：不能承诺当前线上可用。

## 结论要求

每个售后根因至少包含：对象、属性、值、适用范围或时间、支持该事实的本轮证据，以及未确认项。只有规则没有当前事实时，只能给出调查方向。

实时私有事实只能使用本轮成功业务观察。观察必须明确绑定客户所问对象；未带目标筛选的列表、默认首条记录、名称相似记录、聚合值、历史工具结果或仅表示传输成功的响应，都不能证明目标身份、唯一性、明细属性或不存在。观察被截断、投影不完整或对象仍有歧义时，保留不确定性并继续取证或只追问一个会改变调查路径的问题。

售前功能介绍可以依据已确认的产品索引；涉及价格、版本权益、市场、竞品和交付承诺时必须使用当前有效资料，并标明资料日期。
